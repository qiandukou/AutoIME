# 版本管理规则（必须遵守）

> 这份文件是给「以后的我」和「以后帮我改代码的 AI」看的。
>
> **一句话：已发布的版本目录只读，永不修改。要改，就复制成新版本再改。**

---

## 铁律

1. `releases\vX.Y.Z\` 一旦发布，**里面任何文件都不许再改动**（`.cs`、`.exe`、文档全都不许）
   > 例外：`AutoIME.log`、`AutoIME.ini`、`AutoIME.learned.txt` 是运行时自动生成的文件，
   > 不算代码改动（发布检查会自动忽略它们）。
2. 改功能必须走下面的「三步流程」，**绝不允许在旧版本目录上直接改**
3. 版本号只增不减，新版本号必须比现有最新版大
4. 每次改动都要在 `更新日志\CHANGELOG.md` 顶部记一笔
5. 老版本的 `AutoIME.exe` 永远可用——出问题可以立刻退回去
6. **每个新版本必须同时更新这三样，缺一不可**：
   - `releases\vX.Y.Z\AutoIME.cs`（代码）
   - `releases\vX.Y.Z\使用说明.md`（**软件说明**——新功能、新配置项、新限制都要写进去）
   - `更新日志\CHANGELOG.md`（**更新日志**——改了什么、为什么、怎么验证的）
7. 发布前必须跑 `.\发布检查.ps1 <版本号>`，**全部通过才算发布完成**
8. **每次开新版本前，必须先询问用户**：本次是大版本更新（主版本 +1）还是小版本更新（次版本 +1 / 补丁 +1）；按用户确认的类型定版本号，不自行判定

---

## 版本号规则

格式：`主版本.次版本.补丁版本`（三段，例如 `1.1.9`）

| 改动类型 | 版本号 | 例子 |
|---|---|---|
| 修 bug / 行为微调 / 健壮性加固 | 补丁 +1 | 1.1.7 → 1.1.8 → 1.1.9 |
| 加功能 / 改行为 | 次版本 +1，补丁归 0 | 1.1.9 → 1.2.0 |
| 大改结构、配置格式不兼容 | 主版本 +1，次版本 / 补丁归 0 | 1.x → 2.0.0 |

版本号出现在三个地方，必须一致：

- 目录名 `releases\v1.1.9\`
- 源码 `AutoIME.cs` 里 `Ver.Number = "1.1.9"`
- Windows 文件属性里的 `AssemblyVersion` / `AssemblyFileVersion`（三段号补第四段 0：`1.1.9.0`）

`新版本.ps1` 会自动同步这三处并重新编译。

> **先问再定号**：动手复制新版本前，先向用户确认本次属于上表哪一类（大版本 / 小版本），用户拍板后再生成对应版本号；AI 不替用户决定这次算大版本还是小版本。

---

## 三步流程

### 第 1 步：先确认现状（一个字都不要动）

```powershell
cd C:\Users\<你的用户名>\...\AutoIME
Get-ChildItem releases        # 看清当前最新版本，例如 v1.1.8
```

### 第 2 步：复制成新版本

**方式 A（推荐，一步到位）：**

```powershell
.\新版本.ps1 1.1.9
```

它会自动完成：复制最新版本目录 → 把版本号改成 1.1.9 → 重新编译 → 清理运行时文件。
旧版本目录**只读不动**。

**方式 B（手动）：**

```powershell
Copy-Item releases\v1.1.8 releases\v1.1.9 -Recurse
# 然后编辑 releases\v1.1.9\AutoIME.cs 顶部：
#   public const string Number = "1.1.9";
#   [assembly: AssemblyVersion("1.1.9.0")]
#   [assembly: AssemblyFileVersion("1.1.9.0")]
```

### 第 3 步：只在新目录里改

1. 改 `releases\v1.1.9\AutoIME.cs`
2. **改 `releases\v1.1.9\使用说明.md`**（软件说明：新功能、新配置项、新限制、新快捷键都要写清楚；
   哪怕只修了个 bug，也要在说明里把相关描述改对）
3. 双击 `releases\v1.1.9\build.cmd` 重新编译
4. 在 `更新日志\CHANGELOG.md` **顶部**加一节，写清改了什么、为什么、怎么验证的
5. 跑 **`.\发布检查.ps1 1.1.9`**，全部通过
6. 测试通过后，`v1.1.9` 就是新的最新版

> `.\发布检查.ps1 1.1.9` 会检查：旧版本有没有被改动、版本号是否一致、
> **`使用说明.md` 是否真的更新过**、**`更新日志\CHANGELOG.md` 是否还有「待填写」**。
> 不通过就说明还差东西，不许发布。

```
3) 再用 .\新版本.ps1 <新版本号> 复制出下一代版本，只在副本里改；
4) 每次新版本必须同时更新：代码 AutoIME.cs、软件说明 使用说明.md、更新日志文件 更新日志\CHANGELOG.md，缺一不可；
5) 编译用 releases\vX.Y.Z\build.cmd，发布前跑 .\发布检查.ps1 <版本号> 且必须全部通过；
6) 确认 AutoIME.cs 里的 Ver.Number 与目录名一致。

现在我要加的功能是：______________________
```

## 发布前自检清单

- [ ] 新版本号比旧的大；旧版本目录的文件修改时间没有变化（说明没被改）
- [ ] `AutoIME.cs` 里 `Ver.Number` 与目录名一致
- [ ] `build.cmd` 编译通过
- [ ] **`使用说明.md` 已更新**（新功能 / 新配置项 / 新限制都写进去了）
- [ ] **`更新日志\CHANGELOG.md` 已记录**，且没有「待填写」
- [ ] **`.\发布检查.ps1 <版本号>` 全部通过**
- [ ] 在干净环境能启动：自动生成 `AutoIME.ini`，右下角出现托盘图标
- [ ] 三条关键行为没退化：
  - 不在输入框时，输入法处于关闭状态（按键直达软件）
  - 光标进入输入框时，输入法自动打开
  - **键盘布局始终不变**（语言栏不跳）

## 目录约定

```
AutoIME\
├─ README.md              ← 总入口
├─ 更新日志\
│  └─ CHANGELOG.md        ← 更新记录（每次改动都要加）
├─ 版本管理规则.md         ← 本文件
├─ 新版本.ps1             ← 一键生成下一代版本
├─ releases\
│  ├─ v1.1.8\             ← 已发布，只读
│  │   ├─ AutoIME.exe
│  │   ├─ AutoIME.cs      ← 源码副本（给 AI 读）
│  │   ├─ AutoIME.ini     ← 默认配置（首次运行可重新生成）
│  │   ├─ 使用说明.md
│  │   ├─ build.cmd       ← 双击重新编译
│  │   ├─ 安装到本机.cmd
│  │   └─ 卸载.cmd
│  └─ v1.1.9\             ← 下一代（复制出来后才存在）
└─ AutoIME_v1.1.8.zip       ← 可直接拷到别的电脑
```
